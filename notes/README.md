# 笔记体系（notes）

> 项目文档的**唯一权威来源**，是 `docs/` 的替换，不是它的摘要层。

## 定位

- notes **替代 `docs/`**：每篇笔记自洽、可独立读懂，承载原 `docs/` 对应文档的全部内容；不再依赖外部长文，也不「链回源文档」。
- **当前处于迁移期**：`docs/` 仍暂存作为待迁移素材，但已不再新增内容；新内容直接写进 notes。docs 向 notes 的迁移由人工重度参与完成（逐篇把 docs 内容并入对应笔记、确认无遗漏后，再整体移除 `docs/`）。迁移完成交付后，仓库里**只有 notes，没有 docs**。
- **「源文档」行是迁移标记**：每篇笔记里的 `> 源文档：` 记录它替换的是哪篇 `docs/` 文件，便于迁移时核对；`docs/` 删除后此行一并移除。
- 与 dev-log / inbox / todo 的关系：这些当前仍在 `docs/` 下，随 docs 迁移一并处理（人工参与、逐篇确认最终归属），不在本次自动改造范围。

## 单篇结构（强制）

```markdown
# <短标题，≤30 字>

> 一句话：<≤50 字，这篇讲什么>

## 现状
<本文档主题现在是什么样的事实描述。≤1500 字；内容与结构不限——清单、段落、`###` 分节皆可。>

## 本文档不包括什么
- <剔掉的话题，≤100 字>：<剔除理由，≤100 字>
- …（确无可剔除的话题时写 `- 无`）

## 决策记录

> 只增不减：历史决策不改写、不删除，只追加新行。

| 决策时间 | 决策点（≤100字） | 结论（≤100字） | 依据（≤100字） |
| --- | --- | --- | --- |
| YYYY-MM-DD HH:MM:SS | … | … | … |
```

只有这三段 `##`：不得新增、改名、调序。`###` 小标题可用于给「现状」分节 —— 现状的内部结构不限。

## 硬性约束

- **整篇字数不限**（规则正文可完整承载，不必为凑字数牺牲信息）。
- **章节标题白名单**：`##` 层只允许 `现状` / `本文档不包括什么` / `决策记录` 三段，顺序固定、各出现一次；**出现其它 `##` 标题即非法**（脚本报错）。三段内部可以用 `###` 分节（如「现状」按主题分小节）。
- **标题**：文件首个非空行、全文唯一的 `#` 标题；≤30 字，非空。
- **子标题不得重名**：判重按**完整路径**——同一父节下不得出现同名子标题（重名会让人分不清两节的差别）；不同父节下的同名子标题合法（如「现状 / 单测 / 命令」与「现状 / 端测 / 命令」）。
- **现状**：关于文档主题的**事实描述**，≤1500 字；内容与结构不限（清单、段落、`###` 分节皆可），按内容选最清楚的写法。「我们不做什么」属现状事实，写在这里。
- **「本文档不包括什么」是范围剔除**：只用于划掉不属本文档主题的话题，目的是防止「现状」越写越多、偏离主题；**不是「不做的事」的收纳桶**。确无可剔除的话题时写 `- 无`。
- **「本文档不包括什么」必须为清单式**：每条以 `- ` 起头，格式 `<剔掉的话题，≤100 字>：<剔除理由，≤100 字>`，用中文或英文冒号分隔。
- **决策记录**：每行「决策点 / 结论 / 依据」各 ≤100 字；**只增不减**——历史决策不改写、不删除，只追加；纠正旧决策时新增一行说明，不覆盖。
- **决策时间精确到秒**：新决策必须 `YYYY-MM-DD HH:MM:SS`；历史决策只知日期的填 `YYYY-MM-DD`、时间列留空，不编造；确实不知日期则留空。
- **人和 AI 都读**：纯 Markdown、无富文本依赖；表格机器可解析；不写只有人才懂的暗语。
- **隐私脱敏**：落盘前按 AGENTS.md「隐私与脱敏规则」脱敏（相对路径、`<用户名>` 等占位符）。

## 不写什么（水文清单）

- 变更史（"原本…现在已移除"）— 留给 git。
- 推理过程、决策前的纠结 — 只留结论。
- 段落墙、铺垫、客套 — 一条说清就一条。
- 只有人才懂的暗语、缩写无注释。
- **会腐烂的计数**（用例数、文件数、行数、体积）— 每次改动都会变，且没有机制提醒你更新，写进去必然过时、还会误导读者。要表达规模就写**不变量**（"全部单测"）；确有必要的**带日期快照**（`2026-09-17：260 例`）放流水（`dev-log`），不放笔记正文。

## 规范检查

- 脚本：`notes/check-notes.py`（纯 Python，无第三方依赖）。
- 运行：`npm run check:notes`（等价于 `python3 notes/check-notes.py`）—— 遍历 `notes/` 下全部笔记，逐条核对结构（标题、**章节标题白名单**：三段齐全 / 无多余 `##` / 顺序正确 / `###` 在三段内 / 子标题不重名、「一句话」字数、现状 ≤1500、「本文档不包括什么」清单式与字数（`- 无` 视为合法空写法）、决策记录字数与时间格式），打印每篇的偏离项，全部通过则退出码 0。

## 怎么增删改

- 新增：在 `notes/` 下建 `.md`（kebab-case），补 `INDEX.md` 一行；若是替换某篇 `docs/`，在 `> 源文档：` 标出来源。
- 改名：保持 kebab-case；同步 `INDEX.md` 与所有指向它的链接。
- 同步：源文档大改后同步笔记的「现状 / 本文档不包括什么」，让笔记始终保持自洽、可独立读懂。
- 决策记录只增不减：历史行不改写、不删除；新决策追加一行。
- 索引：`notes/INDEX.md` 是总表，唯一事实来源；新增笔记必须登记。
- 校验：新增 / 修改后跑 `npm run check:notes`，确保符合规范。
