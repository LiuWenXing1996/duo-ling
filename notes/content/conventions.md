# 项目约定决策

> 一句话：仍生效的架构约定 + 已否决方案表；改前先读，避免同一问题被重议一遍。

## 现状

### 仍生效架构约定

- **单端架构**：只服务浏览器扩展（Chrome MV3），不抽 `packages/shared` 双端共用层——所有代码只服务扩展。
- **UI 复用**：改 UI 先查 `src/components/` 现有实现，禁照界面重写；用 `src/lib/window-api.ts` 按 `PreloadApi` 契约桥接 `window.api`，组件零改动。
- **手写数据层逐条自检四类语义**：回退 / 守卫（空标题、非法 id、未知 op、空清单）/ 先校验后落盘 / 无变化就不做（幂等短路径）；四类各补单测。常量表（如 `providers.ts`）逐字段核对——服务商预设曾少 7 个就是这么漏的。
- **主题跟随系统**：`src/lib/theme.ts` 用 `prefers-color-scheme` 驱动 `html.dark`；两个载体 html 不写 `class="dark"`（曾固定成纯黑）；新增 UI 用主题变量不硬编码颜色。
- **仓库结构**：`srcDir:'src'` 必须（WXT 内置 `@`/`~` 别名硬编码指向它且覆盖用户 alias）；`publicDir` 显式 `src/public`（否则 `tool-bridge.js` 不进产物）；包管理用 npm，产物 `.output/`。
- **生成物优先让工具自生成**：`.wxt/`、`node_modules/` 等靠装依赖时工具自己建，不靠文档提醒人跑准备命令（详见 `lessons.md` 的 WXT 现象族）。

## 本文档不包括什么

- 双端共用层：单端架构不需要，所有代码只服务扩展。
- 同一否决项记两处：同一事实说两遍，两处会各自过期、互相打架。
- 架构决策理由的详细论证：写在对应 notes 常青篇或本表（一个事实只有一个家）。
