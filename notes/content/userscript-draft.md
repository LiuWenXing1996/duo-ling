# 编辑器草稿

> 一句话：草稿 = git 工作区未提交改动，自动低延迟落盘、重开静默恢复，不污染已保存语义。

## 现状

### 形态

- 草稿 = `/uscripts/<uuid>/` 的**工作区（未提交改动）**，不建独立草稿库。
- 该目录本身是 isomorphic-git 仓，故直接借 git 语义：HEAD = 上次保存、工作区 = 草稿、commit = 保存、改回已保存内容 = 丢弃草稿。

### 三处状态与基准

| 状态 | 位置 | 语义 |
| --- | --- | --- |
| 已保存（**权威**） | 状态库 `duoling-state` | 注册 / 注入依据，含 bundle；写只归 offscreen |
| 已提交 | `/uscripts/<uuid>/.git` 的 HEAD | 历史版本 |
| 草稿 | `/uscripts/<uuid>/{project.json, files/**}` | 未保存的编辑态 |

**判定与回滚一律以状态库为基准，不用 HEAD**：commit 失败不阻断保存主链路，HEAD 可能落后；以 HEAD 为基准会把「已保存但未提交成功」误判成草稿，丢弃时还会退到更旧的版本。

### 通道

- 读写都经 offscreen（fs 实例单例，只在 offscreen 取）：协议 `ai:writeDraft` / `ai:readDraft`，`aiFsClient` 暴露 `writeDraft` / `readDraft`。
- 载荷是**完整 `ScriptProject`**：offscreen 侧要调 `buildContents`，而 UI 侧不能 import `us-git.ts`（会把 isomorphic-git 打进面板包），故 `v` / `uuid` / `createdAt` / `enabled` 由 `baseline` 兜。

### 写工作区的三条不变量

- **纯 fs，绝不动 index**：index 必须停在 HEAD，否则 `statusMatrix` 报不出未提交改动。
- **顺序：清空 `files/` → 重写 `files/**` → 最后写 `project.json`**。写入随时可能中断，`project.json` 是「这批草稿写完了」的提交点，读取方据此判有效性；中间态由保存时全量重写自愈。
- **删除只限 `files/`**，绝不碰 `.git`；清空后重写顺带清掉残留空目录。

### 读取的 null 判据（关键）

`project.json` 读不出 / 解析失败 / 元信息不全 / `files` 为空 → 一律当**没有草稿**。

「有 `.git` 但工作区是空的」是可达状态（建仓成功而快照失败过等）；此时若返回空树，上层会判成「与已保存不等」并拿空内容覆盖编辑态，**直接清空用户脚本**。

### 编辑流

- **打开**：读草稿必须 try/catch，失败 / 超时按无草稿处理；只有草稿非空**且与已保存不等**才静默覆盖编辑态 + 亮提示条 + 置脏。
- 相等判据里**两侧 `config` 必须过同一个归一化**（空数组 → `undefined`）：否则历史数据里的 `excludeMatches: []` 会让每次打开都判成「有草稿」。
- 用草稿填充时两处守卫：入口可能指向已删文件 → 回退第一个文件；头部名称取草稿名兜底已保存名。
- **编辑中**：deep watch 项目字段 → debounce 500ms → **串行化**（防旧内容后到覆盖新内容）→ 无改动不写 → 失败静默（弱提示，不打断编辑）。
- **卸载前 flush**：把 pending 写立即发出（不 await）——debounce 叠加 fs 层自身延迟，最后一段改动本就容易丢。
- **保存**：保存即提交，工作区就是已保存的样子——**不需要「删草稿」动作**；但 `baseline` 必须跟着保存结果更新（builder 可能改写文件树，否则之后丢弃会退到保存前内容）。
- **丢弃**：用 `baseline`重写工作区，**不用 `git checkout HEAD`**；先写成功再动编辑态。
- **恢复历史版本**：整体覆盖工作区 = 隐式丢弃草稿；恢复后重新装载即回到与状态库一致。
- 脏检测两套：编辑期用同步的 `editDirty` 做即时反馈，打开时用内容比对给权威判定。

### 已知代价（已接受）

- **每次编辑都要走 IPC**：fs 实例只在 offscreen；offscreen 常驻，不会因容器不在而失败。
- **草稿随仓一起消失**：仓被对账重建或目录损坏时一起没——草稿是 best-effort 数据。
- **多标签同时编辑同一 uuid**：后写覆盖先写，不做锁（脚本编辑是单人场景）。

## 本文档不包括什么

- 独立 IndexedDB 草稿库：已否决，多一套表示与转换、多一处清理时机、多一套脆弱的脏状态机制。
- 用 `git checkout HEAD` 回滚：HEAD 可能落后于状态库，会退到更旧的版本。
- 草稿进历史 / 产生 commit：草稿不是提交，历史只看已提交版本。
- 并发编辑加锁：单人场景，best-effort 接受后写覆盖。
