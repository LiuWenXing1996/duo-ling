# 提案流程规范

> 一句话：可选工具（决策留痕非门禁）；五态状态机 + 流转记录 + 不可删；文档自包含。

## 现状

提案是**可选工具**，不是门禁（2026-09-17 降级）：日常改动直接做不开提案；重大变更建议开（决策留痕）；拿不准倾向不开。已开提案的规矩不变。

### 五态状态机

| 状态 | 目录 | 可流转到 | 含义 |
| --- | --- | --- | --- |
| 草稿 | `docs/proposals/draft/` | 评审中 / 拒绝 | 还在写，允许推翻重写 |
| 评审中 | `docs/proposals/review/` | 草稿 / 实施中 / 拒绝 | 讨论与修改 |
| 实施中 | `docs/proposals/implementing/` | 实施完成 / 评审中（仅限误转退回） | 已批准，正在实现 |
| 实施完成 | `docs/proposals/done/` | — | 终态 |
| 拒绝 | `docs/proposals/rejected/` | — | 终态 |

- **目录即状态**：流转 = 移动文件 + 在末尾流转记录追加一行；文件名 kebab-case 不随状态改名。
- **不可删除**：提案创建并提交远程后不可删，只能靠状态流转变更；终态提案正文不改，要修正就新开提案引用它。
- **流转记录只增不减**；误转实施中（未经批准）发现即退回评审中，如实记一笔「误转退回」。
- **状态变更与实现代码进同一 PR**，commit 划分不作要求（流转记录表是权威留痕）。

### 提案结构

提案文档自包含（不外链其他文档），必含章节：问题 / 方案 / 备选方案（必填，记下被打败的决策）/ 验收标准（可勾选条目）/ 不做的事 / 决策记录（必填，只增不减）/ 流转记录（创建首条 = 新提案 → 草稿）。标题 ≤50 字；状态须是状态表之一。一个提案只对一个 PR；装不下说明干太多，拆提案不拆 PR。

## 本文档不包括什么

- 分支保护与直推 main：归 AGENTS.md（本文只讲提案自身的状态机与文档结构，不重复合并流程）。
- 想法收件箱 / 需求收集：归 `inbox`（提案只承接已成型的设计，不收需求）。
