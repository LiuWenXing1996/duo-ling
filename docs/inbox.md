# 想法收件箱

> 只装「谁在什么场景遇到什么问题」，**不写方案**。
> 改动后跑 `npm run check:inbox`（查：单条 >100 字、总字数 >6000、「不办」条目缺理由、疑似重复）。

## 规则

1. 每条 ≤100 字，只写「谁在什么场景遇到什么问题」
2. **不写方案**——写出来说明已经处理过了，那该去 [`docs/proposals/`](proposals/)
3. 不排序、不排期、不承诺
4. 进「待办」不代表要做，只表示「这确实是个问题」
5. 移到「不办」必须附一句理由，不许默默删掉
6. **已办直接删**：待办描述的问题被直接修复（没走提案、也没决定不办）的，直接从「待办」里删掉即可，不受上一条「不许默默删掉」约束——它已了结，留着只是噪音
7. **AI 只记不办**：AI 不把「待办」分区当任务清单执行；碰到值得记的念头可以主动问用户要不要加入，但不准不经确认就落笔

与提案流程的区别：这里**没有方案、也不承诺要做**；有方案的走提案流程。

## 待办

- 管理页里的脚本后台静默生效，时间一久用户只剩一串开关：看不出每个脚本是干嘛的、当时为什么建；AI 生成的脚本在会话删除后更是彻底失忆。
- 写 `docs/dev-log/` 时没有内容边界可依，也没有脚本查字数上限；决策留档、踩坑记录、测试现状与未做项混装其中，单日已到上限 3.5 倍。
- 想查「当时为什么这么定」时，`docs/` 顶层的 11 份存量方案文档同时扛方案、状态、结论三个角色，状态行会随实现推进过期。
- 要跟进 AI 生成脚本的未落地方案时，`docs/todo.md` 的方向是最终移除，这些条目当前没有承接去处。（2026-09-17 已缓解：承接去处 = 路线图 `notes/content/userscript-ai-generation-next.md` + 各 `proposals/done/` 归档 + 已收编进本分区「待办」；`todo.md` 已于当日移除）
- 读代码注释时，有一批只写「§x」、不写文件名的引用指向 `userscript-ai-generation.md` 的旧章节号；该文收编后章节已重编，这批号已失效，读者无从定位。
- 老大不在场时，提案人可自行判定「评审已通过」并完成采纳流转：流转执行权无归属规则、采纳类流转不要求附凭据，且提案体检不在 CI 门禁，误转只有手动跑脚本才暴露（2026-09-17 element-picker 误转实例）。
- 对 AI 的回答不满意时，用户只能自己在输入框重新描述一遍要求让它重答，没有现成的「重新生成」手段，旧回答也无法撤掉。

- 关掉侧边栏后，生成任务的进度和结果用户完全看不到，只能干等，缺面板关闭期间的进度通知（提案②）
- 生成任务进行中用户再发消息，现在直接被拒（拒绝 chat:start），体验割裂，缺同会话消息排队（提案②）
- 生成链路搬 offscreen 后每条事件多一次跨上下文跳转，流式观感是否变差没实测过（提案②；chat:chunk 逐条推送）
- 脚本后台静默生效，半年后用户只看到一串开关，不知道每个脚本干嘛的，缺 notes 档案（提案③；对齐工具侧 archive.md）
- zip 只能单文件导入导出，没法拖拽导入、也没法多选批量导出（提案③ 残余）
- zip 不包含 DL.store 数据，备份/迁移脚本时用户数据会丢（提案③ 残余；data/ 备份语义后置）
- 脚本只能 zip 本地分享，没有统一市场分发（提案③ 残余；完整脚本市场另议）
- 注入的脚本看不到页面 JS 全局，拿不到页面运行时状态（DL.page 反向中继，规范稿待评审，随 v2 Phase 4）
- offscreen 单写失败时只弹错误条，没有重试按钮，用户只能自己重来（写失败可重试 UI 提示）
- AI 生成时只能靠 URL/标题/点选拿页面上下文，拿不到整页结构（档 3 自动 DOM 摘要探针明确不做、留后续提案）
- 用户打开工作台默认落在「主页」标签，而它自工具链路移除后就是空壳、不渲染任何内容；首页该放什么一直没定论。
- 编辑器里有未保存草稿时从历史面板恢复某个版本，草稿会被整体覆盖、事先没有任何提示，用户只在事后发现改动没了。
- 写 `docs/dev-log/` 时往里塞什么没边界、内容太杂，需要按类型拆分，把决策/踩坑等非日志内容移除出去（归 notes/）。
- 脚本存储偏离目标设计：状态库 `ScriptProject` 同时含源码 `files` 与产物 `bundle`，源码权威副本也落 `duoling-state`，并非「源码仅 lfs、产物仅 state-db」划分；lfs 实为 offscreen 内 git 版本化工作副本（SW/扩展页读不到 lfs 所致）。需确认是否预期，或标定为已决偏离。
- 产物「仅构建时写、非 offscreen 只读」无存储层硬守卫：`state-db.writeProject` 不校验 `bundle` 来源，仅靠调用方约定（create/update/import 均先 build）+ 单写方收敛保证；目标是硬约束，考虑是否加存储层守卫拒绝非构建路径覆盖 `bundle`。
