# 想法收件箱

> 只装「谁在什么场景遇到什么问题」；**允许 ≤30 字的方案短语点方向，但不装方案设计**。
> 改动后跑 `npm run check:inbox`（查：单条 >100 字、总字数 >6000、「不办」条目缺理由、疑似重复）。

## 规则

1. 每条 ≤100 字，**这 100 字含末尾的方向短语**（不是「100 字问题 + 30 字方向」），方向短语本身再卡 ≤30 字；主体只写「谁在什么场景遇到什么问题」
2. **不写方案设计**——方向词点到为止，禁止展开：不写实现步骤、不写数据结构/IPC 形状、不列 UI 细节、不比较备选、不分期。想得出完整方案说明已经想清楚了，那就直接去做；方案全文写进对应代码或 `README.md` / `AGENTS.md` 里
3. 不排序、不排期、不承诺
4. 进「待办」不代表要做，只表示「这确实是个问题」
5. 移到「不办」必须附一句理由，不许默默删掉
6. **已办直接删**：待办描述的问题被直接修复（没决定不办）的，直接从「待办」里删掉即可，不受上一条「不许默默删掉」约束——它已了结，留着只是噪音
7. **AI 只记不办**：AI 不把「待办」分区当任务清单执行；碰到值得记的念头可以主动问用户要不要加入，但不准不经确认就落笔

## 待办

- 管理页里的脚本后台静默生效，时间一久用户只剩一串开关：看不出每个脚本是干嘛的、当时为什么建；AI 生成的脚本在会话删除后更无从追溯。
- 对 AI 的回答不满意时，用户只能自己在输入框重新描述一遍要求让它重答，没有现成的「重新生成」手段，旧回答也无法撤掉。

- 收起浮层后，生成任务的进度和结果用户看不到，只能等待，缺浮层收起期间的进度通知
- 生成任务进行中用户再发消息，现在直接被拒（拒绝 chat:start），体验割裂，缺同会话消息排队
- 脚本只能 zip 本地分享，没有统一市场分发（完整脚本市场另议）
- offscreen 单写失败时只弹错误条，没有重试按钮，用户只能自己重来（写失败可重试 UI 提示）
- AI 生成时只能靠 URL/标题/点选拿页面上下文，拿不到整页结构（档 3 自动 DOM 摘要探针明确不做、留后续事项）
- 编辑器里有未保存草稿时从历史面板恢复某个版本，草稿会被整体覆盖、事先没有任何提示，用户只在事后发现改动没了。
- 用户在编辑器点「清依赖缓存」后再次保存构建，产物仍立刻产出，疑似仍命中旧依赖缓存（HTTP 磁盘缓存 / 清理未生效待定位），用户无法确认清理动作真的发生了。
- 油猴（Tampermonkey）脚本市场生态丰富，但项目脚本格式与之不兼容，现成脚本无法直接复用。
- 脚本运行状态现在只在页面浮窗的灵动岛里，而浮窗默认收起——用户在扩展图标、popup、页面悬浮按钮上都看不到当前页的脚本跑没跑、有没有报错。方向：考虑这几处也显示运行状态。
- 脚本连续写值会乱序落盘：同步 set/delete 都不等应答，SW 侧并发处理且 delete 读到键不存在即提前返回 —— set 紧跟 delete 可能留下旧值（矩阵探针真机摇摆复现）。方向：写命令按脚本串行化。
- 非 Chrome 用户用不上：Firefox 只到「能构建」（适配停在 sidebar_action、发布链路也不发包），装上只看到降级文案；Edge 同引擎但我们只在 Chrome 上验过。方向：把 Firefox 适配纳入交付面。
- 用户关掉某个站点的接口录制后，已录的内容没有清理入口，只能一直留在本地库里。方向：补一个按站点清记录的入口。
- 接口录制的 AI 路径（浮层卡片渲染 → 开启 → 刷新 → 读回）只验过数据通路，整条流程没在浏览器里端到端跑过，真出问题无从定位。
- 浏览器没开「Allow User Scripts」时，提示只出现在工作台脚本列表的横幅里；平时不开工作台的用户看不到，只会发现脚本一个都不生效。方向：扩展图标加 badge 提示。
- 想直接给 AI 看截图（页面报错、想要的样式、设计稿）时，浮层输入框只收文字，用户只能自己把图里的信息描一遍。方向：输入框支持图片。

- 用户删掉已启用的脚本后，目标页面刷新仍在注入它（面板显示的是已删脚本的注入面），要等 SW 冷启动对账才清净。方向：删除路径并入注册串行队列。

- 让 AI 改已有脚本后，它的收尾文案说「未启用状态，需你确认启用」，而脚本实际仍是启用态（原地更新保留了它）——用户会以为没生效、反复去启用。方向：文案与实际状态对齐。
- 网页浮层的站点开关只呈现当前标签页那一行，用户看不到哪些站点已开浮层、按什么规则命中，无从核对已有设置。方向：列出已配置的站点与规则。
- 网页里的悬浮按钮和展开后的对话浮层位置固定，挡住页面内容时挪不开，也不能按自己的习惯摆到顺手的位置。方向：支持拖拽移动。
