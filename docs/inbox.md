# 想法收件箱

> 只装「谁在什么场景遇到什么问题」，**不写方案**。
> 改动后跑 `npm run check:inbox`（查：单条 >100 字、总字数 >6000、「不办」条目缺理由、疑似重复）。

## 规则

1. 每条 ≤100 字，只写「谁在什么场景遇到什么问题」
2. **不写方案**——想得出方案说明已经想清楚了，那就直接去做；方案全文写进对应代码或 `README.md` / `AGENTS.md` 里
3. 不排序、不排期、不承诺
4. 进「待办」不代表要做，只表示「这确实是个问题」
5. 移到「不办」必须附一句理由，不许默默删掉
6. **已办直接删**：待办描述的问题被直接修复（没决定不办）的，直接从「待办」里删掉即可，不受上一条「不许默默删掉」约束——它已了结，留着只是噪音
7. **AI 只记不办**：AI 不把「待办」分区当任务清单执行；碰到值得记的念头可以主动问用户要不要加入，但不准不经确认就落笔

## 待办

- 管理页里的脚本后台静默生效，时间一久用户只剩一串开关：看不出每个脚本是干嘛的、当时为什么建；AI 生成的脚本在会话删除后更是彻底失忆。
- 对 AI 的回答不满意时，用户只能自己在输入框重新描述一遍要求让它重答，没有现成的「重新生成」手段，旧回答也无法撤掉。

- 关掉侧边栏后，生成任务的进度和结果用户完全看不到，只能干等，缺面板关闭期间的进度通知
- 生成任务进行中用户再发消息，现在直接被拒（拒绝 chat:start），体验割裂，缺同会话消息排队
- 生成链路搬 offscreen 后每条事件多一次跨上下文跳转，流式观感是否变差没实测过（chat:chunk 逐条推送）
- 脚本后台静默生效，半年后用户只看到一串开关，不知道每个脚本干嘛的，缺 notes 档案（对齐工具侧 archive.md）
- zip 只能单文件导入导出，没法拖拽导入、也没法多选批量导出
- zip 不包含 DL.store 数据，备份/迁移脚本时用户数据会丢（data/ 备份语义后置）
- 脚本只能 zip 本地分享，没有统一市场分发（完整脚本市场另议）
- 注入的脚本看不到页面 JS 全局，拿不到页面运行时状态（DL.page 反向中继，随 v2 Phase 4）
- offscreen 单写失败时只弹错误条，没有重试按钮，用户只能自己重来（写失败可重试 UI 提示）
- AI 生成时只能靠 URL/标题/点选拿页面上下文，拿不到整页结构（档 3 自动 DOM 摘要探针明确不做、留后续事项）
- 编辑器里有未保存草稿时从历史面板恢复某个版本，草稿会被整体覆盖、事先没有任何提示，用户只在事后发现改动没了。
- 脚本存储偏离目标设计：状态库 `ScriptProject` 同时含源码 `files` 与产物 `bundle`，源码权威副本也落 `duoling-state`，并非「源码仅 lfs、产物仅 state-db」划分；lfs 实为 offscreen 内 git 版本化工作副本（SW/扩展页读不到 lfs 所致）。需确认是否预期，或标定为已决偏离。
- 产物「仅构建时写、非 offscreen 只读」无存储层硬守卫：`state-db.writeProject` 不校验 `bundle` 来源，仅靠调用方约定（create/update/import 均先 build）+ 单写方收敛保证；目标是硬约束，考虑是否加存储层守卫拒绝非构建路径覆盖 `bundle`。
- 删除已启用的用户脚本后，目标页面里它仍在运行，像是没撤销注册；用户以为删干净了，页面却还跑着（刷新后是否依旧未确认）。
- README「关键坑」列表每次并发 PR 必撞编号：双方各自往末尾追加，rebase 要手工顺延编号、还得回头改 commit message 里的引用。
- 用户在编辑器点「清依赖缓存」后再次保存构建，产物仍秒出，疑似仍命中旧依赖缓存（HTTP 磁盘缓存 / 清理未生效待定位），用户无法确认清理动作真的发生了。
- 脚本数量变多后，列表里一堆脚本难以分辨和定位，缺分组归类手段。
- 油猴（Tampermonkey）脚本市场生态丰富，但项目脚本格式与之不兼容，现成脚本无法直接复用。
