# 0007. GM 规范三道防漂移防线

日期: 2026-10-18
状态: 已接受
代码落点: packages/offscreen-document/src/chat/spec-text.test.ts（文件头指针指回本文件）

## 背景

规范文本（spec-text.ts）是 AI 写脚本时唯一的事实来源。它引用一个不存在的成员、或教 AI 写一个本扩展不认的 `@grant` 名，都不会有任何运行时报错——只会让模型照着错的东西生成脚本，用户看到的只是一份跑不通的脚本。错误必须被测试挡住，而不是等运行期。

## 决策

三道防线，各管一段：

1. **类型层**（gm-api-catalog.test.ts）：目录类型 ↔ 真身。
2. **反射层**（gm-api-catalog.test.ts，从注入源码反射）：注入源码真实挂载的键集合 ↔ 目录——发送侧字符串对 typecheck 不可见，靠反射比对（见 0003）。
3. **文案层**（spec-text.test.ts）：规范文案 ↔ 目录 / grant 名单——能力清单与 `@grant` 一节已由数据生成，这里防的是「有人改回手写」与「手写段引用错名字」。

## 后果

新增 / 改名 GM 能力时，三道都要过；文案与目录的关系是生成而非手抄，手写段里的名字会被测试校验。
