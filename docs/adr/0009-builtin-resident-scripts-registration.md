# 0009. 内置常驻件：注册式常驻与全站匹配

日期: 2026-10-18
状态: 已接受
代码落点: packages/service-worker/src/userscripts/engine.ts（syncFloatHost / 检查器注册 JSDoc 指回本文件；浮层宿主同决策）

## 背景

打开浮层 / 发起拾取的时刻是「页面早已打开、用户刚点按钮」，而注册件只在页面**开始加载**时注入——两者差的正是这个时间点。要在那之后还能挂上对话框 / 接管拾取，只能加载即到位、待命等指令。

## 决策

- 内置件（浮层宿主、页面检查器）走注册式系统脚本（GM 包装注入、MAIN 世界），启动即建常驻通道待命，指令经 DL Port 事件帧下去、结果经脚本桥 `__dlEvent` 信封上来。
- 注册面收敛：走 manifest 通道的声明式内容脚本不在 `getScripts()` 里，UI 只能标一句「常驻」、回答不了「此刻到底在不在」；注册件让内置件全在同一处同步、同一个口对账（listBuiltinRegistrations），「这一页上跑着什么」只剩一个答案。
- MAIN 世界系统脚本：件是只读观察者，页面看得见它做的一切（DOM 本就共享）；世界配置 / GM 包装 / 脚本桥随统一注册链自动就位，不再单独 configureWorld。
- 判据差异：录制件看「有没有页在录」，检查器件**恒在**。

## 备选与否决

- **manifest 声明式内容脚本**：不进注册面对账体系，且同样回答不了「此刻在不在」。

## 代价与后果（已确认接受）

- 浮层的可用性从此与「允许运行用户脚本」开关**绑定**——开关关掉时浮层也挂不出来（声明式内容脚本不受该开关影响）；popup 探活不应答，界面上有可用性横幅说明该开关在哪。
- **匹配面全站**：注册没有 tab 维度（RegisteredUserScript 的匹配字段全是 URL），打开目标由用户点按钮那一刻决定，只能覆盖全部——每个普通网页里都有一份待命代码（零 UI、零网络：只建一条通道与一个 MutationObserver，连 DOM 都不建）。
