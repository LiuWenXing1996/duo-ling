# 0003. 命令名运行时登记表：让注入源码字符串进 typecheck

日期: 2026-10-18
状态: 已接受
代码落点: packages/shared/src/api-contract.ts（`API_COMMANDS`，运行时登记表）

## 背景

命令的**发送侧**是 gm-wrapper.ts 里那段注入源码**字符串**（`__gmSend({ c: 'store.get' … })`），命令名对 typecheck 完全不可见——拼错、或改了 dispatch 漏改包装层，编译与分层单测都不报。

## 决策

- 立一份可在运行时枚举的登记表，形状取 `Record<ApiRequest['c'], true>`，由 api-commands.test.ts 从真实注入源码**反射**发送侧、与它双向比对。
- 形状是刻意的：键约束 + 对象字面量的多余属性检查，使「契约加了命令、表没跟上」与「表里写了不存在的命令」**都编译报错**——本表不可能成为第二真相源。
- 与 `default` 分支的穷尽性检查互补：那条管分发侧，这条管发送侧。
- 顺序按字母（前缀天然成簇）；新增命令时在 `ApiRequest` 与本表各加一行。

## 备选与否决

- **不加登记表**：命令名永远在 typecheck 盲区里。
- **宽松类型（`string[]` / 普通对象）**：双向漂移都拦不住。
