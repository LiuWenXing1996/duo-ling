# 用户脚本 · zip 导入导出方案（分享语义）

> 状态：**已实施**（2026-09-17）。方案定稿 v1 于 2026-09-15；**准入语义于 2026-09-17 修订**为「只拦原则项、尽量导入」（见 §5.2–§5.4）。
> 替代 [userscript-v2-plan.md](./userscript-v2-plan.md) §Phase 3 第 5 条的「待方案」状态。

## 1. 目标与非目标

**目标**：脚本分享闭环——把脚本打包成 zip 给别人，对方一键导入。v1 只做**分享**语义。

**非目标（明确后置 / 不做）**：

| 项 | 处置 |
| --- | --- |
| 备份/迁移（含 `DL.store` 运行数据） | 后置。zip 格式预留 `data/` 目录位，v1 恒空；将来做备份时以导出开关（「包含脚本数据」）形式补。理由：分享是主场景且无隐私顾虑，掺入 store 值后 zip 会携带用户浏览痕迹类数据，分享时反而危险 |
| 油猴 `==UserScript==` 格式兼容 | 不做。粘贴安装已随旧管理器删除（2026-09-15），zip 是自有格式 |
| 多选批量导出 | 后置（checkbox 态要改列表组件）。v1 = 每行导出 + 全部导出 |
| 内容指纹去重 | 不拦截。重复导入同一 zip = 两个独立副本（uuid 重生成），报告提示即可（§5.6） |

## 2. 依赖

**fflate**（~8KB、零依赖、同步 API，比 jszip 小一个量级）——本方案唯一新增依赖，**已批准并落地**。

## 3. zip 格式 v1（导入导出共用，一次定死）

```
<脚本名>/                      # 目录名仅展示用，去重时加 -2 后缀；真名以 project.json 为准
  project.json                 # 见下
  files/
    main.js                    # 真实文件树展开：路径 = 项目相对路径
    lib/util.ts
  data/                        # v1 恒空，备份语义预留位（§1）
...（多脚本 = 多个平级目录）
```

**`project.json` 字段**：`v: 1`（schema 版本）、`name`、`config`（`ScriptConfig` 原样）、`entry`、`exportedAt`（导出时间）、`exporter`（`duoling/<扩展版本>`，排障用）。

**明确不进 zip 的**：`bundle`（派生物，导入侧现场构建；构建失败不阻断、只缺产物，见 §5.3）、`uuid`（本机标识，导入方重生成）、`enabled`（导入恒为 false，见 §5.5）、`createdAt/updatedAt`（导入方以导入时间为准）。

**files 展开成真实文件而非内嵌 json 的理由**：人可读；对方不用哆灵也能直接看/改 zip 里的源码，改完还能导回——「分享」的语义才成立。

## 4. 导出

- **入口**：列表页（`UserscriptListPanel`）每行菜单加「导出」+ header 加「全部导出」。单脚本导出 = 只含该脚本目录的 zip，文件名用脚本名；
- **范围**：只列活跃脚本，`deprecated` 旧 GM 记录不导出（格式不同、不可编辑，有损转换不值得）；
- **隐私提示**：导出确认处固定一句文案——「导出内容包含脚本源码明文，请注意其中是否有凭据」。files 是明文，用户很可能把 token / 内网地址写死在脚本里（本项目自己的隐私红线，产品里要有同样的意识）；
- **实现面**：ui-client 现成的 `getProject` / `list` 只读方法即可，**不新增协议命令**；编解码放独立纯函数模块（`src/lib/userscripts/zip-transfer.ts`，探针脚本放 `tmp/`）。

## 5. 导入

### 5.1 入口

列表页「导入」按钮（file picker）+ 拖拽 zip 到列表区（后者可选增强）。

### 5.2 解析与准入（2026-09-17 修订：只拦原则项）

**判据**：能构造出记录就导入；其余一律放行并在报告里说明，留给脚本编辑器修。

**唯一跳过（原则项）**——没有可解析的 manifest 就构造不出任何记录：

- 顶层目录缺 `project.json`；
- `project.json` 非合法 JSON，或不是对象（数组 / 标量）。

**放行（尽量导入 + 报告说明）**：

| 情形 | 处置 |
| --- | --- |
| 路径不安全（`..` 段 / 盘符 / 绝对路径 / 反斜杠） | **只过滤该文件**（进报告「未导入的文件」），脚本其余文件照常导入 |
| `project.json.v` 任意值 | 不校验（开发期无版本规范） |
| `name` 缺失 / 非法 | 以 zip 目录名兜底 + 报告说明 |
| `entry` 缺失 / 非法 | 以默认入口 `main.js` 兜底 + 报告说明 |
| `config` 缺失 / 非法 | 逐字段兜底（`matches` 空、`allFrames` 默认 true、`runAt` 默认 `document_end`）+ 报告说明 |
| `matches` 非法 | 不校验，原样落库（启用时报错，见 §5.4） |
| `files` 为空 / `entry` 不在 `files` | 放行（构建期失败见 §5.3） |

- `files/` 之外的顶层条目（含 `data/` 预留位）**未导入**，汇进报告「未导入的文件」，不报错；
- **目录名 ≠ 真名**：`name` 存在时以它为准，缺失时以目录名兜底。

### 5.3 构建（尽力，不阻断）

zip 不带 bundle，导入侧在 offscreen 内现场构建：与 `createProject` 同构（先构建、后落盘）。

**构建失败不淘汰**（2026-09-17 修订）：脚本照常落盘（`bundle` 缺省），报告提示带 esbuild 的 `文件:行:列`。可注册性由启用时兜底——`resolveInjectCode` 无产物即抛错并记 `register` 警告，**绝不会把未构建源码注入页面**；用户在编辑器改到能构建，保存即补上产物。

这同时是导入校验：zip 是外部数据，`project.json` 长得对不代表能跑；构建是确定性验证器，把「拷贝时少了依赖文件」的残缺 zip 当场暴露。注意：远程依赖源码已物化进 files（`builder.ts` 的 dl-vfs 插件），**导入含 CDN 依赖的 zip 不需要网络**。

### 5.4 matches 校验位置

导入时**不校验** match pattern（2026-09-17 修订）：非法值不阻断导入，原样落库。

校验器 `validateMatchPatterns` 仍在**启用路径**（`engine.registerScript`）执行，以中文报出「哪条规则不合法」，用户带着这条信息去编辑器改。理由：以「尽量导入 + 报错引导修复」为准，而非「入库前淘汰」。

### 5.5 三个已定默认值

| 项 | 默认 | 理由 |
| --- | --- | --- |
| uuid | **重新生成** | uuid 是本机标识；保留原值则两台机器互导第二次必撞 uuid |
| 重名 | **保留原名，允许重名**（2026-09-17 修订） | uuid 才是唯一标识，名字本就不拦重复；指纹重复提示照做，观感区分靠报告与时间戳 |
| enabled | **false（停用）** | 导入脚本是任意来源代码；落盘 → 用户审源码 → 手动启用。与 AI 生成「先落盘不启用」同一产品原则 |

**完整链路**：选 zip → 解析（只拦原则项，其余兜底放行）→ 尽力构建（失败也不淘汰，只缺产物）→ 落盘（停用态）→ 用户审源码 / 编辑器修 → 手动启用 → 注册注入。「启用」动作本身**永不触发构建**（启停零构建是既有设计），产物来自导入时那次构建或用户最近一次保存。

### 5.6 重复导入

不做拦截。导入报告对内容指纹（hash files + entry）与现有脚本一致的条目标一句「与现有脚本「X」内容相同（仍已导入）」——提示但不替用户做决定（故意要一份副本改着玩是合理场景）。

### 5.7 失败语义

**逐脚本独立**：只有解码层的原则项（无 `project.json` / 非合法 JSON / 非对象 manifest）才产生失败条目；其余一律落盘——构建失败、字段兜底、路径过滤都记在**成功条目的提示**里。报告汇总「成功 N 个，失败 M 个 + 原因 + 未导入 N 个文件」。不做整包回滚。

### 5.8 成功动线

- 导入成功后**不自动进编辑器**；统一停在列表页并弹出汇总报告（成功 N / 失败 M + 原因 + 提示 + 指纹重复提示 + 未导入的文件）。
- 新导入的脚本在列表行标「刚导入 · 未启用」，用户手动启用或点编辑；启用后摘标。单脚本 / 多脚本走同一套动线。
