# 文档管理规范

> 类型：规范（常青）
> 状态：现行
> 更新：2026-09-14
> 归档条件：常青，不归档
> 前置阅读：[AGENTS.md](../AGENTS.md) §全局约束（隐私与脱敏）

docs/ 下所有 Markdown 的**分层、元数据、索引、归档**规则。写新文档、改状态、移动文件前先读本文件。

---

## 1. 背景：这份规范要解决什么

2026-09-14 盘点时 docs/ 有 13 篇、3135 行，问题是结构性的：

1. **平铺无分层** —— 规范、在办方案、已完结方案混在同一层，读者（人 / AI）无法据此判断「这篇现在还算不算数」。
2. **状态靠自觉** —— 每篇文件头各写各的（`状态：已实施` / `已定稿，实施中` / `⚠️ 补充`），没有统一字段，也没有「什么条件下归档」。
3. **索引脱节** —— AGENTS.md 的文档职责总表只列 8 条，实际 13 篇，漏掉 5 篇。漏掉等于 AI 不会去读。
4. **死内容占位** —— 已下线链路的方案仍占正文，Electron 时期的踩坑仍留在 lessons.md 前排。

核心原则：**文档有生命周期，完结即归档；没被索引的文档等于不存在。**

---

## 2. 三区分层

| 区 | 目录 | 放什么 | 准入 | 退出条件 |
| --- | --- | --- | --- | --- |
| **常青** | `docs/`（根） | 现行规范、现行设计、已实施功能的权威说明 | 内容持续有效、随代码演进 | 不归档（除非被新规范取代，取代即删） |
| **在办** | `docs/wip/` | 方案稿、实施计划、待评审设计 | 有明确终点（实施完 / 被否决） | 实施完 → 精华并入常青后归档；被否决 → 直接归档 |
| **归档** | `docs/archive/` | 已完结、已废弃、已下线 | 从上面两区移入 | 不再维护，只读参照 |

判定口诀：**「问它半年后还有没有人需要读」——有 → 常青；只在做完之前有用 → 在办；做完了/不做了 → 归档。**

`legacy/` 是另一回事：它是整个 Electron 实现的归档，不归本规范管。

## 3. 文件头部元数据（强制）

每篇文档开头必须有一个引用块，字段按此顺序，缺项写 `—`：

```markdown
> 类型：规范 | 方案 | 记录
> 状态：草稿 | 实施中 | 已实施 | 现行 | 已废弃
> 更新：YYYY-MM-DD
> 归档条件：<什么情况下移入 archive，或「常青，不归档」>
> 前置阅读：<可选，相对路径>
```

字段含义：

| 字段 | 规则 |
| --- | --- |
| 类型 | 规范 = 约束性要求；方案 = 还没做完的设计；记录 = 踩坑 / 待办 / 事实清单 |
| 状态 | **草稿 / 实施中 / 已实施** 只用于「方案」；**现行** 只用于常青文档；**已废弃** 表示内容已失效但暂不删 |
| 更新 | 内容有实质变更就改日期，不是创建日期 |
| 归档条件 | 必须可判定。写「做完就归档」不算，要写「实施完成并入 xxx 后归档」 |

旧文档在迁移时补齐头部（见 §8）。**状态变化必须改「更新」日期**，否则读者无法判断新鲜度。

## 4. 命名与体量

- 文件名 **kebab-case**（对齐 [style.md](./style.md) §1）；根目录例外：`AGENTS.md` / `README.md` 保持大写。
- 单篇软上限 **250 行 / 30 KB**。超限必须二选一：
  - 开头加**章节索引表**（§号 + 一句话 + 「哪个场景读哪章」），让读者按需跳读；
  - 按主题拆成多篇。
- 体量不是罪，无法按需读才是。62 KB 的方案若没有索引，AI 每次都得整篇吞。

---

## 5. 索引：AGENTS.md 文档职责总表是唯一入口

规则（**新增 / 移动 / 归档 / 删除文档，必须同一次改动里更新总表**）：

1. 总表只列 **常青区 + 在办区**。**归档区不进总表**（要考古自己去 `docs/archive/` 翻）。
2. 每行三列：文档链接、职责、「何时读」。「何时读」必须写具体触发场景，不能写「需要时」。
3. 归档区在总表下方留一行说明指向 `docs/archive/`，学 `legacy/` 的写法。
4. AI 的读取顺序固定为：**AGENTS.md → 文档总表 → 命中的单篇**。禁止一次性把整个 docs/ 灌进上下文。

## 6. 写作硬约束

| 约束 | 说明 |
| --- | --- |
| **隐私脱敏** | 落盘前按 AGENTS.md §隐私与脱敏规则处理：本机绝对路径、用户名、token、内网 IP 一律占位符化 |
| **不引用未入库内容** | 禁止把 `.workbuddy/memory/`、`tmp/` 等**不进 git**（见 `.gitignore`）的内容当权威源引用。决策结论必须落在 docs/ 或代码里，否则换机器就断链 |
| **代码优先** | 文档与代码冲突时**以代码为准**，并立即更新文档。不要为了让代码符合文档而改代码 |
| **相对路径互引** | 文档间一律用相对路径（`./xxx.md`、`../AGENTS.md`）。移动文件必须同步改所有引用方 |
| **不重复事实** | 同一件事只在一个地方权威定义，其他地方用链接。重复定义必然漂移 |

## 7. 归档流程（4 步）

1. `git mv docs/<file>.md docs/archive/<file>.md`（保留 git 历史，别新建文件）。
2. 头部补一行 `> 归档：YYYY-MM-DD · 原因：<一句话>`，状态改成对应值（已实施 / 已废弃）。**正文不改**。
3. 从 AGENTS.md 文档总表删除该行；若它在总表里被其他条目引用，同步改路径。
4. 全仓搜该文件名，修掉所有引用（含其他文档与代码注释）。

归档文档里的方案若仍被现行设计依赖，先把**结论**抄进常青文档，再归档原文。
