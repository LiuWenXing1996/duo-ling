**落地内容**：

- **错误 ID 修复闭环**：错误记录的 `id` 字段复用既有 `crypto.randomUUID()`（自评审修正：原稿「需新生成短 ID」不实），工作台展示前 8 位、复制完整 id；`error_read` 支持 8 位以上唯一前缀匹配（多命中 = ambiguous，绝不猜）。链路：`userscript:errorRead` 命令（`extension-ipc.ts`）→ SW 读 `us:errors` → offscreen `error_read` 工具。`script_read` 直读 uuid 为既有能力，本期零改动。
- **工作台错误日志**：`UserscriptListPanel.vue` 按脚本分组渲染 + ID 展示 / 复制按钮；深链 `#/errors/<uuid>` 打开脚本列表并定位过滤（`WorkbenchApp.vue` 补 `hashchange` 监听——工作台已开时 `tabs.update` 只改 hash 不重载，`onMounted` 不再跑）。
- **#2 完成徽章**：chat-host 收尾（成功 / 停止 / 异常统一走 `cleanup(ok)`）推 `chat:finished`；SW 旁听后视「面板端口存活」决定是否点亮 `setBadgeText('1')`。面板存活 = `ChatApp.vue` 挂载时连 `duoling:panel` 长连接（断开 = 面板关了）；`sidePanel.onOpened` 与端口连接都清零。监听器全部收进 `defineBackground`（模块顶层注册会让 extension-ipc 协议测试踩到 fakeBrowser 未实现 `onConnect`——见下「测试」）。
- **测试**：`match-pattern` / `status-bubble` 内核 / `findUserScriptError` 前缀匹配新增单测；extension-ipc 协议测试补 `userscript:errorRead` case（SW 侧）。typecheck + 291 例单测 + build 全过。

**#8 实测（真实链路，探针在 `tmp/chunk-probe.spec.ts`，不入库）**：mock OpenAI 兼容 SSE 服务（2ms 间隔推 3000 个 content delta ≈ 24KB，模拟「生成一个大脚本」的最坏节奏）→ 播种模型配置指向 mock → 真实 sidepanel 输入框发送 → 面板内探针记录 chunk 到达时刻 + rAF 长帧统计。

- 结果：3007 chunk 全部到达（7.6 秒流完），间隔 avg 2.5ms / p50 2.5ms / p95 3.3ms / max 106.7ms，>32ms 长帧仅 3 个。
- 结论：**逐条推送的开销远低于可感知掉帧阈值，无需改批量**——维持现状设计。

**坑（Node mock SSE 一行都吐不出）**：探针第一版卡死在「收到 start 后永远等不到后续」——mock 服务里 `req.on('close', () => clearInterval(timer))` 是元凶：新版 Node 的 `IncomingMessage` `close` 事件在**请求体读完时**就触发（不再等连接断开），流式计时器刚起就被清掉。清理必须挂 `res.on('close')`。详见 [lessons.md](../lessons.md)。

**遗留**：E2E 只覆盖扩展冒烟，浮窗 / 徽章的真实行为依赖手测（提案验收清单里已标注手测项）。
