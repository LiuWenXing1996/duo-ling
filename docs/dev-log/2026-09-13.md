# 2026-09-13 · Electron → 浏览器扩展：方案、Spike 与一期落地

## 迁移方案与评审

产出 `docs/plugin-migration-plan.md`。核心结论：**可转，复用率高**，能力契约 / UI 层 / agent 编排可平移，`isomorphic-git` 配 `lightning-fs` 几乎零改。

最大改动在三处：

- 承载层：webview → sandbox iframe + srcdoc
- 存储：fs → IndexedDB
- 文件能力语义：任意路径读取消失，需用户授权 / 拖入

对照实际代码评审后修正 7 处（lightning-fs 异步改造、toolId 来源解析缺失、安全白名单随存储平移、git/记录清理一致性、side panel 跨端判断、能力契约变更联动 AI 生成器、host_permissions 上架审查低估），工作量上调至约 0.8–1.0× 桌面版。

## Spike 验证：最险的三处假设全部证伪

起 WXT 最小工程跑通「popup 承载 sandbox iframe + background 能力运行时 + lightning-fs/isomorphic-git 版本闭环」，报告见 `docs/plugin-spike-report.md`（该文件已删除，git 历史可查）。

**服务 worker 里的 Node 全局缺失（三个连环坑，迁移一期必踩）：**

1. `global` 为 undefined → `isomorphic-git` / `lightning-fs` 打包代码写 `global.TextEncoder` 读 undefined 即崩，连带 SW 注册失败（表现为 `Service worker registration failed. Status code: 15`）。修法：`wxt.config.ts` 的 `vite.define` 加 `global: 'globalThis'`，并在 `background.ts` 最前 import `src/polyfills.ts` 兜底。
2. 修完 `global` 后报 `Buffer is not defined` → SW 无 Buffer/process 全局。修法：新建 `src/polyfill-process.ts`（先补 process，buffer 包加载会引用）+ `src/polyfills.ts` 随后 `import { Buffer } from 'buffer'` 挂 `globalThis.Buffer`，二者均在 `background.ts` **最前** import（保证早于 isomorphic-git）。
3. 改 `wxt.config.ts` 必须重启 `npm run dev`（HMR 不重读配置），再到 `chrome://extensions` 点刷新图标重载扩展。

**sandbox iframe 焦点 + CSP 连环坑：**

- 仅 `allow-scripts`（opaque origin）→ 内联脚本能跑，但 popup 内 iframe 输入框抢不到焦点（无光标）
- 加 `allow-same-origin` 修焦点 → 同源后扩展 CSP 拦截内联 `<script>`（unsafe-inline），桥接不执行
- 最终修法：桥接脚本抽成外部同源文件 `public/tool-bridge.js`，srcdoc 改 `<script src="/tool-bridge.js">`，toolId 经 `<body data-tool-id>` 传

> ⚠️ **安全底线**：正式迁移中 AI 生成的**不可信**工具页必须回严格 sandbox（opaque origin），可信桥接与不可信 UI 拆两层 iframe，否则会把 chrome API 暴露给不可信代码。上面为修焦点加 `allow-same-origin` 的做法只适用于自研工具页。

**其他：** WXT 给 side_panel 自动补的 `sidePanel` 权限曾误判为"非法"并剔除，导致加载失败；`@wxt/vue` 已下架改用 `@vitejs/plugin-vue`；回滚功能原 `git.checkout({ ref: 'HEAD' })` 是"恢复当前版本"等于没退，应 checkout 到 `HEAD~1`（`git.log` 的 `log[1].oid`）。

## sidePanel 权限的重要更正

曾误判 WXT 自动补的 `sidePanel` 为非法权限并用 `build:manifestGenerated` hook 剔除，**这是错的**：Chrome 官方明确 `sidePanel` 是使用 `chrome.sidePanel` API 的必需合法权限（Chrome 114+），且 `setPanelBehavior({ openPanelOnActionClick: true })` 还需 manifest 声明 `action` 键。

当时加载失败的真正根因是 SW 的 `global.TextEncoder` 崩溃，与权限无关——两者曾被混为一谈。

正确配置：`permissions: ['storage', 'sidePanel']` + `action` 键 + `side_panel.default_path`，`setPanelBehavior` 放顶层（幂等，比只依赖 `onInstalled` 稳）。

**跨端事实**（MDN 核实后修正）：Firefox **有** sidebar，但用独立体系——`sidebar_action` manifest key + `browser.sidebarAction` API；Chrome 用 `side_panel` + `chrome.sidePanel`。二者不互通，WXT 只生成 Chrome 侧。正确做法是抽「工作台」独立组件，由 side panel / `sidebar_action` 面板 / options 共用，代码层按浏览器条件分发 API。

## 形态决策与一期结构

- **工作台形态 = side panel**（不用 popup）。
- side panel 承载 AI 对话界面；设置 / 工具代码 / git 版本改由**独立标签页**呈现（`workbench.html` + hash 路由 `#/tools`、`#/tool/<id>/<run|code|history>`、`#/settings`）。
- 对话链路：**扩展页直跑 AI SDK `streamText` + `toUIMessageStream`**（扩展页有 host_permissions 可直连，比桌面版少一层主进程事件推流）。会话与消息存 IndexedDB，模型配置存 `chrome.storage.local`（⚠️ 无 safeStorage 等价物，Key 明文存本机，已在设置页明示）。
- `host_permissions` 由 `providers.ts` 的 `providerOrigins()` 推导。

**WXT 工程化坑：**

- `srcDir: 'src'` 必须显式设置，且 `publicDir` 要显式写 `src/public`（详见 [conventions.md](conventions.md)）
- **entrypoint 同名冲突**：同时存在 `sidepanel.html` 与 `sidepanel.ts` 时 WXT 报 "Multiple entrypoints with the same name"，入口脚本要用非约定名（如 `app/sidepanel-main.ts`）由 html 引用
- 编译严格度对齐：WXT 默认开 `noUncheckedIndexedAccess`、legacy 没开，项目 tsconfig 覆盖为 `false`
- ambient `.d.ts` 不能有顶层 import/export，否则 `declare module` 退化成模块增强报 TS7016

## 结构重构：legacy 归档 + 扩展上移

用户拍板「根上重构，原码归档」：Electron 工程配置与源码全部移入 `legacy/`，扩展工程内容上移到仓库根，删除空的 `browser-extension/`。

**`legacy/` 故意不 ignore**——否则 git 会把移动判定为纯删除，丢掉历史关联。重构提交被 git 正确识别为 rename（671 个 R100），历史关联保住。

## UI 平移：对话层 + 工作台

起因：一期手搓的 10 个组件完全没复用 legacy 的 481 个。分步复用，先对话层后工作台，依赖引进 293 包，平移脚本按闭包复制 196 + 231 文件。

平移踩坑（后续同类平移必看）：

1. WXT 硬编码别名并覆盖用户配置 → 唯一解法 `srcDir: 'src'`
2. WXT 的 publicDir 基于 root 而非 srcDir
3. 随 srcDir 迁移目录：`entrypoints/`→`src/entrypoints/`、`public/`→`src/public/`
4. 编译严格度要对齐（见上）
5. ambient .d.ts 不能有顶层 import/export
6. **覆盖共享文件前必须备份**：用 legacy `shared/types.ts` 覆盖工作区版本时，丢掉了未提交的扩展侧类型（后按引用点重建并拆到 `extension-ipc.ts`，但过程有损）
7. Shimmer 的 `motion[tag]` 类型需收敛（`as unknown as Component`）

链路选择：新增 `src/lib/extension-chat-transport.ts` 渲染层直跑 AI SDK，取代手搓 transport 与平移来的 `custom-chat-transport.ts`；新增 `src/lib/window-api.ts` 按 `PreloadApi` 契约装配 `window.api`，未平移能力用递归 Proxy 兜底（调用即抛带路径错误），平移组件因此零改动。

**遗留**：产物 16.77 MB（大头是 shiki 全量语言包，可改按需加载）；agent 编排未接；工具页子资源无协议可解析（目前只能单文件 HTML）；同源 sandbox 的分层硬化未做。

## 桥接层全量对照 legacy 的修复

用 `scripts/compare-bridge.py` 逐函数 diff。已修：

- `conversation-store.ts`：首条用户消息自动命名失效（被拆成独立导出函数却无人调用，桌面版在 `appendMessage` 内触发）；`renameConversation` 补 trim + 空标题拒绝；`totalTokens` 改为由消息 usage 派生；新建会话序号改自增（原用 `list.length+1` 会重号）

- `tools-data.ts` / `storage.ts`：补保留键守卫（原 `clearToolsData('modelProfiles')` 能把模型配置一起删掉）
- `providers.ts`：服务商预设少 7 个且展示名不一致 → 按 legacy 原文逐条重排；`providerOrigins` 只取 supported（AWS 无 baseUrl，不上权限）
