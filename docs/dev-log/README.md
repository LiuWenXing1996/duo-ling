# 开发日志

本目录记录**项目通用知识**：架构决策、方案评审结论、通用技术坑、未完成项清单。
它随 git 分发，是给未来的维护者（人和 AI）看的，不是流水账。

## 与 `.workbuddy/memory/` 的区别

| | `docs/dev-log/`（本目录） | `.workbuddy/memory/` |
|---|---|---|
| 归属 | 项目资产，**入库** | AI 工具的本机工作区，**不入库** |
| 读者 | 未来的维护者与 AI | 当前会话的 AI |
| 生命周期 | 长期保留、随分支传递 | 临时，worktree 删除即消失 |
| 内容 | 提炼过的结论 | 原始过程记录 |

`.workbuddy/` 是工具的内部目录，结构可能随工具版本变化，也不适合承载项目知识。
**不要把项目知识写在 `.workbuddy/` 下**——那里写的东西会随 worktree 一起消失。

## 写什么 / 不写什么

**写：**

- 架构决策及其理由（为什么这么定，不只是定了什么）
- 方案评审的结论与偏差（实施时与方案的出入，下次照方案时该注意什么）
- 通用技术坑（换机器、换人还会再踩的）
- 未完成项与已知边界
- 关键代码位置（文件:行），便于后续定位

**不写：**

- 本机环境细节（沙箱、授权、包管理器路径、IDE 行为、锁文件）
- 临时状态（"未提交""视觉未确认""待拍板"）
- 会话过程与对话称呼
- 个人 ID、仓库远程地址、IP、凭据

写之前先问一句：**这条换台机器、换个半年还成立吗？** 不成立就不写进这里。
