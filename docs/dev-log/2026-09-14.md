## 布局优化第 2 步：脚本列表标签页

新增 `src/components/userscript/UserscriptListPanel.vue`，边界是**不改 `UserscriptManager`**（那是另一个入口的全屏覆盖层，含新建 / 编辑器 / 错误面板）。

决策与实现要点：

- 数据通道 `userscriptClient` 直接 `chrome.runtime.sendMessage`，**不走 `window.api`**——workbench 是可信扩展页，而 `window.api` 是给平移来的桌面版组件用的 `PreloadApi` 契约
- 启停**不做乐观更新**：`await` 成功后才改本地状态，注册失败必须如实反映
- 用 shadcn `ui-switch` + `ui-switch-thumb`（项目里首次使用），没有复制 `UserscriptManager` 里那套手写 `role="switch"` + 硬编码色
- **不加 `panel-header`**：跟随 `DeveloperPanel` 样板，标签名已标明这是脚本列表，避免标题重复

**坑：**

- `formatTimestamp(ts)` 收的是 Unix **秒**（内部 `new Date(ts * 1000)`），而 `ScriptSummary.updatedAt` 是**毫秒**（`Date.now()`），直接传会显示 1970 年 → 用 `Math.floor(ts / 1000)` 换算
- `ui/switch/switch.vue` 只有 `<slot />`、**不带内置 thumb**，必须显式传 `<ui-switch-thumb />`，否则开关没有圆点
- `WorkspaceTabs.vue` 的图标分支 `v-else-if` **必须放在 `v-else` 兜底之前**，否则会落到设置图标

**零输入创建脚本**：`userscript:create` 零参数，自动命名（「新建脚本」+ 重名递增，用 `listSummaries()` 含 legacy 旧记录查重）、默认 `enabled: true`、`['*://*/*']`、极简模板。**初始模板必须纯 JS、不能含 import/export**——否则 `resolveInjectCode` 以「项目未构建」拒绝注册（新建不跑 esbuild）。创建时即 `snapshotProject` 建仓 + 首次提交（原先首次建仓发生在第一次保存）。仓位失败不阻断（与保存链路同策略：仓损坏只丢历史不丢脚本）。

## dev 启动失败：web-ext 不创建 chromiumProfile 目录

`npm run dev` 构建成功后立刻退出，报 `ENOENT ... .chrome-dev-profile/chrome-out.log`。

**根因链**（逐层读源码 + 最小复现验证）：

1. `wxt.config.ts` 的 `webExt.chromiumProfile` 指向 `.chrome-dev-profile` 并开 `keepProfileChanges: true`
2. `web-ext` 的 `ChromiumExtensionRunner.setupInstance` 在 `keepProfileChanges` 分支**只校验 userDataDir、不创建它**
3. `chrome-launcher@1.2.0` 的 `Launcher.prepare()`：`this.userDataDir = this.userDataDir || this.makeTmpDir()`——**只在自己造临时目录时才建目录**，外部传入的路径它直接 `openSync(<dir>/chrome-out.log)`

**为什么现在才炸**：`.chrome-dev-profile/` 是 gitignore 的本地产物，在**新建的 git worktree / 新 clone** 里该目录从未被创建，主仓库那份存在所以那边能跑。

**修复**（`wxt.config.ts`）：

```ts
const chromiumProfileDir = resolve(process.cwd(), '.chrome-dev-profile')
mkdirSync(chromiumProfileDir, { recursive: true })
```

**调试手法（可复用）**：报错栈顶在 `node_modules` 里的 ENOENT，直接读该处源码确认「谁该建目录 / 谁只读不建」，再用 `node -e` 构造最小复现（构造 Launcher + 只调 `prepare()`，零副作用、不开浏览器），比跑整条 `npm run dev` 快且干净。

## lfs 与 git 操作迁至 offscreen

把 lfs + isomorphic-git 操作从 SW 迁到 offscreen document（`docs/offscreen-fs-migration.md` 落地）。

新增 `src/lib/userscripts/us-fs.ts`（`LightningFS('duoling')` 实例，offscreen-only）、`offscreen-fs-commands.ts`（`ai:*` 命令面 + `reconcileFs` 对账）；删 `src/lib/idb-fs.ts`（被 `us-fs.ts` 取代）。

**消息路由关键机制**：`ai:*` 走 `chrome.runtime.sendMessage` **共享总线**；SW 对 `ai:` 是 `onMessage` 监听器 `return false`（不处理、消息继续广播，不是转发）；offscreen 必须补 `onMessage` 分发分支并按 `{ ok, data | error }` 信封回传，否则 UI 的 `send()` 收不到响应。

**踩坑 1 — 上一轮 Edit 失效导致运行时崩溃**：手测「创建脚本」报 `snapshotProject is not defined`。根因是上一轮多处 Edit **实际未落盘**却被当成功。

> **元因（重要）**：WXT/Vite 构建默认**只转译不 type-check**，未定义标识符 build 不报、运行时才炸——上次 build 通过是「假绿」。交付前必须 `npm run typecheck`，不能只看 build。

**踩坑 2 — 读历史报「port closed」**：`ai:*` 只有 offscreen 监听处理，而 offscreen **空闲会自关**、扩展重载/崩溃也销毁它，导致 `chrome.runtime.sendMessage` 无人响应。修法：`ui-client.ts` 新增 `sendAi()` 封装——发 `ai:*` 前先 `send({ kind: 'offscreen:ensure' })` 唤起容器，遇「port closed / Receiving end does not exist」类错误则 ensure 后稍候重试（最多 3 次）。

**offscreen 生命周期决策**：改为**常驻、随时可用**，原「空闲 N 分钟自关」退出条件撤销。三处确保容器在场：`onInstalled`（安装/更新）、新增 `onStartup`（浏览器启动）、SW 冷启动顶层 `void ensureOffscreen()`。`sendAi` 的 ensure + 重试保留为双保险（极端内存压力下 Chrome 仍可能关 offscreen）。

## 草稿方案：工作区即草稿

评审 `docs/userscript-draft.md` 时发现的事实问题：

- **offscreen 是常驻的**，且是通用执行宿主（esbuild 构建 + AI 编排 + git 历史 fs），非仅 AI 生成。早期注释说"按需创建"已过时
- **lfs 是 vanilla `new LightningFS('duoling')`**，offscreen-only 单实例。所谓"落整份 superblock / 整块刷盘"不准确：lightning-fs 文件数据按 path 存于 `-files` store，改一个文件只重写该文件记录 + 小的目录树 superblock 元数据记录
- UI→offscreen→lfs 这条路技术上能通，反对理由全是设计质量层面（无用 IPC 跳、共享 superblock 元数据耦合、命名空间污染、文件树语义错配 KV），无硬性技术阻断

**终局方案（用户拍板）：草稿 = git 工作区的未提交改动。** `/uscripts/<uuid>/` 本身就是 isomorphic-git 仓，草稿就住在工作区，保存 = commit，丢弃 = 工作区回到已保存态。

实现要点：

- 新增 `writeWorktree` / `readWorktree`，**纯 fs、绝不动 index**（动 index 会让 `statusMatrix` 报不出未提交改动）；与既有 `syncWorktree` 的区别就在它含 `git.add`/`git.remove`
- **判定与回滚一律以 storage 为基准，不用 HEAD**：`snapshotProject` 失败不阻断保存主链路，HEAD 可能落后于 storage，回滚到 HEAD 会退到更旧版本。discard 用 `buildContents(baseline)` 重写工作区，不用 `git checkout HEAD`
- 删除脚本无需额外清理：`deleteRepo` 已整目录删除，草稿随之清除
- **草稿写是 IPC 异步，多次写入会乱序，必须串行化**（in-flight promise 或 seq）
- 代价（已接受）：每次编辑必走 IPC（lfs 仅 offscreen 持有）；草稿进入仓的爆炸半径
