## 首页脚本删除后「最近编辑」不刷新（跨面板同步缺失）

**根因**：首页 `scripts` 是挂载时取的一次快照，只在 `onCreate`/`onImportFile` 主动 `refresh()`；脚本在列表页 / 编辑器 / 侧边栏被删后，主页常驻组件无感知、不刷新，已删脚本仍挂在「最近编辑」。

**修复**：`WorkspaceHomePanel.vue` 在 `onMounted` 注册 `chrome.storage.onChanged` 监听，过滤 `us:gm:`（删除即清该键，background `clearGMValues` 行为）与 `us:errors` 前缀变更 → 调 `refresh()` 重拉列表；`onUnmounted` 注销。加 `typeof chrome` 守卫保证测试/happy-dom 安全。无需改 background 基础设施，HMR 即生效。

**回归测试**：`WorkspaceHomePanel.component.test.ts` 新增用例——注入 `chrome.storage.onChanged` 捕获回调，模拟列表页删除 `us:gm:u1` 后断言 `list()` 被再次调用、最近编辑记录从 2 条降为 1 条。组件单测 5/5 通过。

**教训**：常驻面板的数据若只在自身动作时刷新，必须订阅外部变更源（本项目 = chrome.storage.onChanged 的 `us:gm:*`/`us:errors`），否则跨面板操作会留下过期快照。

## 决策变更：移除【最近编辑】入口（废弃跨面板同步方案）

**背景**：上一段用 `chrome.storage.onChanged` 监听做跨面板同步，用户手测仍报「列表页删除脚本后，最近编辑没清除」。

**根因（比上次更深，两处叠加）**：
1. `WorkspaceHost.vue` 的 shadcn Tabs 设 `:unmount-on-hide="false"`——隐藏的标签页内容**不卸载**，主页组件常驻，`onMounted` 只在首次挂载跑一次，切回主页不重新拉数据；
2. background 的 `clearGMValues` 删除脚本时只 `remove` 那个 `us:gm:<uuid>` 键；而默认停用的导入脚本**本就没写过该键**，`remove` 对不存在的键不触发 `onChanged` → 监听收不到 → 不刷新。即 storage 监听对默认停用脚本的删除天然失灵，是假同步。

**决策（用户拍板）**：不纠结跨面板实时同步，直接移除「最近编辑」列表入口（唯一强依赖 per-script 实时数据的区块，删除滞后最刺眼）。概览卡保留（统计数字偶发滞后可接受，不涉及具体脚本行的清除）。

**改动**（仅 `WorkspaceHomePanel.vue`，+ 删死文件）：
- 移除「最近编辑」区块（`v-if="hasScripts"` 列表 + 点击 emit edit）；空状态从「最近编辑的 else」改为独立 `v-if="!hasScripts"` 区块；
- 移除 `justImported` ref 及 `onImportFile` 里的赋值、「刚导入 · 未启用」徽标逻辑；
- 移除 `chrome.storage.onChanged` 监听（`onStorageChange` + `onMounted`/`onUnmounted` 注册注销）；`onMounted` 只剩 `void refresh()`；
- 删除未接线的死文件 `src/lib/userscripts/change-bus.ts`（本准备做页面内事件总线，决策后不再需要）；
- `WorkspaceHost.vue` 第 210 行过期注释改为「添加脚本经 @edit 开编辑器」；
- 组件测试：删两条依赖最近列表/同步机制的用例，补「有脚本不显空状态」「导入合法 zip 调 importZip」两条，共 5 例。

**验证**：typecheck ✓ / build ✓ / 组件单测 5/5 ✓。

**教训（修订上一段）**：上一段「常驻面板必须订阅 storage.onChanged」结论不严谨——storage 键不存在时监听失灵，且本项目隐藏 tab 不卸载使问题更隐蔽。per-script 实时列表类需求，要么用页面内事件总线（同源多面板共享 JS 上下文）显式广播写操作，要么不放常驻面板、由路由级挂载；寄望 storage 语义同步不可靠。本期选「移除入口」规避。
