# 元素拾取器 · 页面上下文增强（提案 ①）

> 状态：评审中
> 来源：[AI 生成用户脚本 · 后续功能路线图](../userscript-ai-generation-next.md) #1 / #6 / #10
> 提案人：

## 问题

AI 生成用户脚本的质量上限卡在页面上下文：目前只有档 0（当前标签 URL / 标题），用户说「把这个按钮改成红色」时，AI 不知道按钮在哪——选择器全靠从 URL 猜，命中率低。三个具体缺口：

1. **元素拾取器（档 2）缺失**：用户在页面上指哪，AI 应该拿到哪块元素的真实信息（结构、属性、可用的选择器），现在拿不到。
2. **页面结构信息缺失**：除了 URL / 标题，AI 对页面本身一无所知——用户不点选元素时，AI 连站点结构都看不到。
3. **内置脚本没有承载位**：拾取器这类随扩展分发的脚本，没有自己的「内置」分组，将来会混进用户脚本列表。

## 方案

### 注入通道：`chrome.userScripts.execute()` 按需注入（Chrome 135+）

拾取器必须在**已加载的页面**上立即生效。选定 `chrome.userScripts.execute()`（Chrome 135+）：按 tabId 向目标标签注入扩展包内的拾取器代码，官方语义「页面已加载则立即运行」，**无新权限**（userScripts 权限已在），原生支持 `worldId`。

- **两大模式都走它**：拾取模式注入交互脚本；快照模式注入静默采集脚本。都是用户点按钮的那一刻才注入，平时页面里没有哆灵的任何代码。
- **超时兜底（唯一新增实现细节）**：用户在拾取期间关闭/导航页面会让注入脚本的 Promise 永不结算，扩展侧 60 秒超时视为取消并提示；注入本身失败时 `execute()` 直接 reject，报错明确（不存在「无应答」态）。
- **代价**：`minimum_chrome_version` 133 → 135（manifest 改动、非权限；worldId 本就依赖 133，只差 2 版。老大 2026-09-17 拍板接受）；Firefox 不支持 `execute()`（MDN 兼容表 No support），FF 拾取/快照能力随三期跨端再补降级路径。
- **世界选型结论不变**：`execute()` 原生带 `worldId`，仍用独立世界 `us-builtin-picker`；世界 messaging 默认 false 正好——本方案不走消息，连 `configureWorld` 都可省（默认 CSP 为 ISOLATED 级，拾取器不 eval）。
- 排除 MAIN 世界的论据保留：它唯一收益（页面 JS 全局）对拾取器零需求，且无扩展 API、postMessage 中继可被页面伪造。
- **连带收益**：无注册 → 无 `registerAllEnabled` 清扫冲突、无固定 id 管理、无版本残留、扩展更新不影响拾取器可用性（代码随扩展包分发，不依赖 userScripts 注册表）。

### 回传通道：`execute()` 返回值，消息链路整体蒸发

路线图曾把本案标注为「唯一改动 DL 桥契约的一项」——按本方案这个前提**更不成立**，在此修正：

- 官方语义：注入脚本求值为 Promise 时，**浏览器等待结算并把结果值带回给 `execute()` 调用方**。拾取模式下脚本返回「用户点选时才 resolve」的 Promise，载荷（元素全量快照）直接从返回值拿回；快照模式同理返回 HTML 字符串。
- 原设想的「USER_SCRIPT 世界 `sendMessage` → SW 独立监听器 → 转发侧边栏」三段链路**整体不需要**；身份校验（`scriptId` 核对）随消息链路一并消失——扩展自己注入的代码，不存在伪造面。
- **不经 DL 桥的结论更彻底**：连消息都不发，`api-contract.ts` / `dl-bridge.ts` / 包装层零改动照旧。

### 拾取器交互与载荷形态

**交互**：

1. 侧边栏输入区两个动作，各自发起一次 `chrome.userScripts.execute()`：**「点选元素」**（拾取模式，注入交互脚本，页面亮出拾取态）与**「附上页面快照」**（快照模式，注入静默采集脚本，无任何 UI）。注入失败 / 60 秒超时（用户关页、导航）→ 明确报错提示，见注入通道兜底。
2. 拾取模式下：鼠标悬停高亮元素框（样式带命名空间前缀，不污染页面）；点击选中（事件在 capture 阶段拦截并 `stopPropagation`，页面自身不响应）；Esc / 右键取消。
3. 拾取结果与页面快照都以 chip 形式显示在输入框上方（「已点选：〈文本摘要 / 标签〉」/「已附页面快照」），随**下一条消息**作为档 2 / 快照上下文发出；可点 × 清除，可重新触发。一次拾取一个元素、至多附一份快照。
4. 面板关闭期间完成拾取 / 快照的结果直接丢弃（都是即时手势，可接受）。

**载荷形态：摘要进提示词，全量按需读**。拾取器一次性采集**超集快照**回传，消费分两层：

| 层 | 载体 | 内容 |
| --- | --- | --- |
| 摘要层 | system prompt（随 chat:start 常驻） | `tag` / `id` / `classes`、白名单关键属性（`name` / `type` / `placeholder` / `aria-label` / 截断 `href`）、≤3 条候选选择器 × **命中数**、文本样本 ~200 字符、HTML 截断 ~500 字符；整层 ≤2KB |
| 全量层 | 新 agent 工具 `element_read`（与 `script_spec` / `script_read` / `script_apply` 并列） | 拾取时的完整快照：全部属性、完整 outerHTML（宽松上限 ~32KB，防极端节点）、可选 parent 链。AI 对摘要层有不确定时**自行调用**，不用不调——token 只在实际读取时花 |

两条要点：

- **同类计数留在摘要层**：AI 自证选择器唯一性不需要额外读一次，命中数必须常驻可见。
- **「按需读」读的是拾取那一刻的快照，不是活页面**。AI 没有回查活 DOM 的通道，页面也随时可能变化——拾取时用户所指的那一块，以快照为准。全量层 = 快照的完整部分，不是实时查询。

### 页面快照（原档 1）：同一唤醒通道的第二种模式

原设想的「扩展页 `fetch` 目标 URL 拿源码」**弃用**：源码对 SPA 无效，且与渲染后 DOM 有差异时会误导选择器；而 MV3 下监听页面网络请求拿响应体是死路（`webRequest` 拿不到 body），自动附源码还让每条请求背上固定 token 开销。改为：

- **「附上页面快照」动作**：与「点选元素」同为一次 `execute()`，快照模式**不亮任何 UI**，静默抓取渲染后的 `documentElement.outerHTML`，截断 ~32KB 从返回值带回，显示为输入框上方 chip，随下一条消息进 `pageContext`。
- **快照即渲染后 DOM**——AI 拿到的就是选择器实际要跑的那个 DOM，服务端渲染内容也在其中（渲染 DOM 是源码的超集），SPA 同样覆盖，无源码误导问题。
- **两个动作都是用户显式点击**：页面内容只在用户说「给」的时候才离开页面，隐私语义与档 2 完全一致，不需要档 3 式的「自动读取需显式告知」设计。
- offscreen `buildSystemPrompt` 组装时标注「渲染后页面快照（截断）」。

### 档 3：本案不做

自动全页 DOM 摘要探针成本与告知复杂度都高（把整页结构送模型，落地前必须显式告知用户），且拾取器已覆盖「用户所指的那一块」。留待后续提案，见「不做的事」。

### 内置脚本承载：不进状态库，「内置」分组只读渲染

状态库写入**只归 offscreen** 是设计红线，SW 或扩展页种子写入内置项目会破单写方契约。绕开：

- 拾取器源码随扩展包构建（产物代码随包分发，经 `execute()` 的 `ScriptSource` 注入），**既不作为 `ScriptProject` 进状态库，也不注册进 userScripts 注册表**——SW 启动注册、固定 id 管理都不需要，`registerAllEnabled` 的清扫式写法与它天然无交集（前稿的「清扫误删坑」随常驻休眠方案一并消失）。
- 管理页新增「内置」分区：从扩展包内置清单（构建期生成）只读渲染，展示名称 / 说明，**无编辑、无删除、无启用开关**——内置脚本不存在「未启用」状态。
- 未来再添内置脚本（如 DL.page 中继的辅助件）只需往清单加条目，分组已就位。

### 改动面

- 拾取器本体：新模块（构建为扩展包内文件），含拾取交互 / 静默快照两种入口 + 载荷采集
- 侧边栏调用封装：新模块，`execute()` 调用 + 60 秒超时兜底 + 失败报错（`worldId: 'us-builtin-picker'`）
- `src/shared/extension-ipc.ts` + `src/shared/types.ts`：`pageContext` 扩展可选字段（快照 HTML、元素摘要 + 全量快照）
- `src/lib/extension-chat-transport.ts`：`collectPageContext` 随带已采集的快照 / 元素上下文
- `src/lib/offscreen-chat/chat-host.ts`：`buildSystemPrompt` 组装新档位（档 2 只进摘要层）
- `src/lib/offscreen-chat/script-tools.ts`：新增 `element_read` 工具（读拾取快照全量层）
- 侧边栏 `ChatPanel`：两个动作按钮 + chip + 超时 / 失败提示
- 管理页列表：内置分组（只读）
- `wxt.config.ts`：`minimum_chrome_version` '133' → '135'（不新增任何权限）
- SW 与 DL 桥：**零改动**

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| 常驻休眠的内置 userScript（前两稿方案） | 免版本号改动 + FF 路径可用，但代价清单长：全站常驻注入（每个页面躺着哆灵代码）、版本残留（旧页面等下次导航才换新）、`tabs.sendMessage` 能否投递进 USER_SCRIPT 世界未验证（文档未承诺——全案最大赌注）、三段消息回传链 + 身份校验、`registerAllEnabled` 清扫坑。评审指出选项清单漏了 `execute()`；核实官方文档后确认其以「最低版本 +2、FF 延后」把上述全部消掉，老大拍板改选 |
| `chrome.scripting.executeScript`（原首选） | 注入足迹同样干净，但 manifest 要新增 `scripting` 权限；且无 execute() 的「Promise 结算值带回」语义，回传链路仍需自建。被 `execute()` 全面替代 |
| 走 DL 桥新增命令（如 `DL.bridge.send`）回传 | 要动 `api-contract` / `dl-bridge` / 包装层三处契约，还解决不了「已加载页面注入」——绕一圈回到注入通道问题；拾取器根本不是用户脚本，不该进用户脚本的消息协议 |
| 采集时定死 ≤4KB 组合包（原方案） | 截断发生在采集时刻，AI 无法回调——截断恰好切走关键结构时就只能猜。改为「摘要 + 按需读」后，截断只影响 token 成本、不影响信息完备性 |
| 只回传选择器字符串 | 载荷最小，但复杂页面一个选择器说不清位置，AI 仍要猜；丢掉了消歧所需的属性与结构 |
| 只回传局部 HTML 片段（不发选择器） | AI 看得到结构但要自己写选择器、无从验证唯一性；同类计数是让 AI 自证的关键，不能省 |
| 内置项目种子写进状态库（管理页数据源统一） | 破「写只归 offscreen」红线，要么破例要么把种子逻辑塞进 offscreen 启动路径，两个都比只读渲染贵；内置脚本没有用户可改的状态，进库没有收益 |
| 档 1 = 每条请求自动 `fetch` 源码（原案） | 源码对 SPA 无效，且与渲染后 DOM 有差异时会误导选择器；MV3 下监听页面网络请求拿响应体是死路（`webRequest` 拿不到 body）、`chrome.debugger` 有调试横幅、hook 页面 fetch 要进 MAIN 世界且只抓得到注入后的新请求。渲染后快照是源码的超集（SSR 内容也在 DOM 里），fetch 无存留价值 |
| 档 3 自动 DOM 摘要探针一并做 | 与拾取器同属「页面上下文」但验收独立、需显式告知 UI，塞进本案会让验收清单失去「逐条可勾」性质 |

## 验收标准

- [ ] `minimum_chrome_version` '133' → '135' 已入 manifest，不新增任何权限（拍板记录见决策记录）
- [ ] 侧边栏点「点选元素」→ 已加载页面立即出现高亮拾取态，无需刷新；非拾取期间页面零哆灵代码（无预注入）
- [ ] 载荷经 `execute()` 返回值拿回；拾取期间用户关闭 / 导航页面 → 60 秒超时视为取消并明确提示（超时逻辑单测覆盖）；注入失败走 `execute()` reject 的明确报错
- [ ] 点击选中后面板出现 chip；Esc / 右键可取消；页面自身在拾取期间不响应点击
- [ ] 摘要层（≤2KB）随生成请求进 system prompt：选择器候选（≤3 条）× 命中数 + 关键属性 + 截断 HTML / 文本（单测覆盖 prompt 组装）
- [ ] 全量快照随 `pageContext` 到达 offscreen（≤32KB 上限），`element_read` 工具可拉全量属性 / outerHTML / parent 链（单测覆盖工具）
- [ ] 「附上页面快照」：静默抓渲染后 outerHTML 截断 ~32KB 显示为 chip，随下一条消息进上下文；prompt 标注「渲染后页面快照（截断）」（单测覆盖 prompt 组装；SPA 页面同样可用）
- [ ] 管理页出现「内置」只读分组，展示拾取器，无编辑 / 删除 / 启用控件
- [ ] DL 桥契约文件（`api-contract.ts` / `dl-bridge.ts`）与 background SW 零改动
- [ ] `npm run typecheck` + `npm run build` + `npm run test` 全过

## 不做的事

- **档 3 自动 DOM 摘要探针**：留后续提案；落地前需显式告知用户的 UI 设计另议
- **页面内容不自动附带**：拾取与快照都只在用户显式点击时采集，不做「每条生成请求自动附页面信息」
- **Firefox 的拾取 / 快照能力**：`userScripts.execute()` FF 不支持（MDN 兼容表 No support），随三期跨端补降级路径，本期 Chrome-only
- **DL 桥契约任何改动**：拾取器不走 DL 协议（本方案下连消息都不发）
- **iframe 内元素拾取**：本期只拾主 frame，`allFrames` 场景后置
- **多元素连续拾取 / 框选**：一次一个元素
- **后台自动改脚本**：既有闸不变，拾取器只是给 AI 更好的输入，生成的脚本仍默认未启用
- **接管路线图 ② ③ 的任何条目**：进度通知 / 消息排队 / regenerate / zip / notes 均不在本案
