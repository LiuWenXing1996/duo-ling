# 建立想法收件箱 docs/inbox.md

> 状态：草稿  
> 来源：  直接提案
> 提案人：[LiuWenXing1996](https://github.com/LiuWenXing1996) + AI

## 问题

现在没有地方能放「只有问题、还没想好怎么做」的东西。

- 想到什么要么憋着，要么当场摊成方案——逼着自己在问题还没看清时就做设计决策
- 载体缺位是既成事实、不是推测：`AGENTS.md` 文档总表、`doc-standard.md` 开头说明、`doc-standard.md` 归属表三处都写着「想法收集箱见 ideas.md」，而 `docs/ideas.md` 在仓库里不存在——三处全是死链。载体被建过又没了，现在连「该往哪扔」都没答案

判据是清楚的：**有没有方案**。有方案的进 `docs/proposals/`，没方案的现在无处可放。

## 方案

新建 `docs/inbox.md`，规范写在文件开头，下面是「待办」「不办」两个分区。有以下规则：

1. 每条 ≤100 字，只写「谁在什么场景遇到什么问题」
2. **不写方案**——写出来说明已经处理过了，那该去 `docs/proposals/`
3. 不排序、不排期、不承诺
4. 进「待办」不代表要做，只表示「这确实是个问题」
5. 移到「不办」必须附一句理由，不许默默删掉
6. **AI 只记不办**：AI 不把「待办」分区当任务清单执行，只有用户明确要求记一条时才往里写

与 `docs/todo.md` 的关系（方向声明）：**最终形态只保留 `docs/inbox.md`**。移除 `docs/todo.md` 属独立变更，**须另开提案**——包括它里面已定稿方案的去处，以及它现有的 5 处引用（`AGENTS.md` 1 处、`doc-standard.md` 4 处）。本提案不动它。

膨胀处理：它明确是会持续增长的文档，纳入 `doc-standard.md` 的软上限表（3000 字）。超了按「清掉已升级成提案的条目 → 合并重复条目 → 提额」的顺序处理，不直接提额。

自动校验：新增 `scripts/check-inbox.py`（npm 命令 `check:inbox`），**与 `check:proposals` 平级、互不依赖**——提案检查管的是提案流程，这个是 inbox 的条目规则，两者不是一回事，不合并也不互相调用。检查三项：单条 >100 字、`inbox.md` 总字数 >3000、「不办」条目缺「理由：」前缀。提醒级：有问题退出码 1，**不进 CI**（与 `check:proposals` 现状一致，都由人按需跑）。

实施动作：

1. 创建 `docs/inbox.md`（两个分区留空）
2. 新增 `scripts/check-inbox.py` 与 npm 命令 `check:inbox`
3. `AGENTS.md` 文档总表新增一行指向 `docs/inbox.md`
4. 三处 `ideas.md` 死链（`AGENTS.md` 1 处、`doc-standard.md` 2 处）改指向 `inbox.md`
5. 移除 `doc-standard.md` 开头「想法收集箱与提案只在『来源』字段碰头」的描述——本提案不再设这个接口，留着是错的
6. `doc-standard.md` 软上限表新增 `docs/inbox.md` 3000 字一行

收件箱长这样（仅示意格式，文件创建时两个分区均为空）：

```markdown
# 想法收件箱

## 规则
> 把上面说的规则单独逐项写入
> 1. ...
> 2. ...

## 待办

- 待办 1
- 待办 2
- 待办 3

## 不办

- 不办事项 1 —— 理由：XXX
```

## 备选方案

- **GitHub Issues + `idea` 标签**：外部贡献者能提、天然可讨论。但想法该是「低成本扔进来」的东西，走 Issue 要建号、选标签、想标题，门槛反而更高；且 AI 得联网调 `gh` 才能读写，离线时记不下来
- **`docs/ideas.md`**：与 `proposals/` 平行、直白。但「ideas」不带处理状态，容易被写成「想法的正式清单」，正是 todo.md 走过的老路
- **一条想法一个文件（`docs/ideas/` 目录）**：检索和链接方便，但把「随手写一句」变成「新建一个文件」，抬高了扔东西进来的成本
- **`docs/todo.md` 加个分区**：一个文件搞定、不用新建载体。但它**只有「待办」没有「不办」**——名字就写死了「这是要做的事」，装不下「想清楚了但不做」的条目；而「待办 / 不办」成对才构成处理状态，正是 `ideas.md` 输掉的同一个理由
- **不建载体，想法直接开提案**：等于要求每个想法诞生时就得有方案，与问题本身矛盾

## 不做的事

- 不动 `docs/todo.md`：本次既不迁移它的内容，也不删它——那是另一篇提案的事（见方向声明）
- 不在 inbox 里写方案、排期、优先级
- 不把 inbox 做成提案的前置队列
- 不给 inbox 与提案之间设任何结构化链接（原设想的「来源」字段引用已取消，见实施动作第 5 条）
